# Customer Churn Prediction

A full-stack machine learning application that predicts which telecom customers are likely to
cancel their subscription, estimates the annual revenue at risk, and suggests a retention action.

- **Business problem:** reduce customer churn and protect recurring revenue
- **Dataset:** Telco Customer Churn (IBM sample data) from Kaggle - 7,043 customers, 20 features
- **Backend:** Flask REST API
- **Frontend:** Streamlit + Plotly
- **ML model:** Logistic Regression vs Random Forest (best model picked by ROC-AUC)

## Quickstart

### 0. Get the dataset
Download **Telco Customer Churn** from Kaggle
(https://www.kaggle.com/datasets/blastchar/telco-customer-churn), unzip it, and save the CSV as:

```
data/telco_churn.csv
```

(The original file name is `WA_Fn-UseC_-Telco-Customer-Churn.csv` - just rename it.)

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Train the model
```bash
python train_model.py
```
This saves `model/model.pkl`, `model/metrics.json` and the evaluation charts.

### 3. Start the Flask backend
```bash
python backend/app.py
```
API runs at **http://localhost:5000**

### 4. Launch the Streamlit frontend
*(open a second terminal)*
```bash
streamlit run frontend/ui.py
```
UI opens at **http://localhost:8501**

### 5. (Optional) Generate the Word report
```bash
python generate_report.py
```
Save screenshots of the three Streamlit pages in `report_images/` as `ui_predict.png`,
`ui_insights.png` and `ui_model.png` **before** running this and they are added automatically.

## API Endpoints

| Method | Endpoint      | Description                                              |
|--------|---------------|----------------------------------------------------------|
| GET    | `/health`     | Health check                                             |
| POST   | `/predict`    | Churn probability, risk tier, revenue at risk, actions   |
| GET    | `/dataset`    | Dataset as JSON (`?limit=500`)                           |
| GET    | `/insights`   | KPIs and churn rate by segment                           |
| GET    | `/model_info` | Model metrics, top churn drivers, input schema           |

### POST `/predict` - example
```json
// Request
{
  "gender": "Female", "SeniorCitizen": "No", "Partner": "Yes", "Dependents": "No",
  "tenure": 12, "PhoneService": "Yes", "MultipleLines": "No",
  "InternetService": "Fiber optic", "OnlineSecurity": "No", "OnlineBackup": "No",
  "DeviceProtection": "No", "TechSupport": "No", "StreamingTV": "No",
  "StreamingMovies": "No", "Contract": "Month-to-month", "PaperlessBilling": "Yes",
  "PaymentMethod": "Electronic check", "MonthlyCharges": 70.0
}

// Response
{
  "churn_probability": 0.81,
  "prediction": "Churn",
  "risk_tier": "High",
  "annual_revenue_at_risk": 680.4,
  "recommended_actions": ["Offer a discounted 1- or 2-year contract to lock in the customer.", "..."]
}
```
`TotalCharges` is optional - if omitted it is estimated as `tenure x MonthlyCharges`.
Invalid or missing fields return HTTP 400 with a list of errors.

Model Performance page). Replace this note with your own numbers, e.g.:

| Metric  | Value |
|---------|-------|
| ROC-AUC | (your result) |
| Recall  | (your result) |
| F1      | (your result) |

Risk tiers are set in `backend/app.py` (`HIGH_RISK`, `MEDIUM_RISK`) and can be tuned to the
retention team's capacity.
